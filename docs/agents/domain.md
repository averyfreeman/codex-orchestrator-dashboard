# Domain docs

Treat the dashboard and docs site as one project context. Shared decisions live in the root `docs/adr/`; the shared glossary belongs at the repo root if one is created.

## Before relevant work

Read the root `GLOSSARY.md` when present and the ADRs relevant to the area. The existing `AGENTS.md` project-context guidance also applies: for host control, SSH routes, Codex profiles, Herdr, or telemetry, read `docs/architecture.md`, `CONTEXT.md`, and relevant ADRs. For protocol integration or measurement-strategy changes, also read `docs/research/interactive-control-options.md`.

If the glossary does not exist yet, continue without flagging its absence. The domain-modeling skill can create it when terms or decisions are clarified.

Use glossary terms consistently and call out conflicts with existing ADRs.
